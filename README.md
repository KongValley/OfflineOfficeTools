# 离线办公工具

Electron 离线办公工具合集,面向 **Windows 7 32 位(ia32)**,zip 解压即用,不联网、不装驱动、不写注册表。

## 使用

解压 `release/离线办公工具-x.y.z-ia32-win.zip` 得到一个文件夹,双击其中的 `离线办公工具.exe` 即可,无需安装。

## 功能

| 工具 | 能力 |
|---|---|
| PDF | 合并、拆分(按连续段或每 N 页)、提取、右旋/左旋/180°、删除范围页、缩略图预览选页、点击顺序重排页面、导出 PNG/JPG(按 DPI)、提取文本、压缩图片(档位或自定义目标 DPI) |
| PDF 整理 | 加页码(位置/格式/颜色/起始号)、清除元数据、四周裁剪边距、目录书签(按字号自动生成/读取当前书签/手写文本回写)、文字水印(居中或平铺、透明度、角度、颜色) |
| 图片 | 批量预览、百分比缩放、按最大边长等比缩放、转换 PNG/JPEG/BMP、JPEG 质量压缩、左右旋转 90°、任意角度旋转、合成 PDF(A4/Letter/原图像素页面、0–72pt 留白、按 DPI 重采样、可选按文件名排序) |
| 文本 | GBK/GB18030/UTF-8/UTF-16LE(BE) 互转、编码自动识别、去重行、行排序、去空行、正则替换 |
| Markdown | 双栏实时预览(相对路径图片自动内联)、导出单文件 HTML、导出 PDF |
| 小工具 | 金额大写(人民币)、日期间隔与工作日推算、日期加减、待办清单 |

六个工具都支持把文件直接拖进窗口,效果与点「选择」按钮一致(原生文件对话框仍可用于挑选/多选);切换标签页会保留已选文件与编辑内容。Markdown 预览里的 http(s) 链接交给系统浏览器打开,不会把应用窗口导航走。

「PDF 整理」一次处理一个文件:加页码固定 9pt 灰/黑/红/蓝,距边缘 24pt,格式支持 `第{n}页`、`{n}`、`第{n}页/共{total}页`、`-{n}-`;裁剪只改 CropBox(0–200pt),不重排内容;自动书签按字号阈值(默认 14)逐页挑标题,层级统一为 1 级,可在文本框里改成 `层级|标题|页码`(如 `1|第一章|1`、`2|1.1 背景|2`)再保存;水印是真实文字,在阅读器里可选中、可搜索。

「小工具」页的待办存在用户数据目录 `%APPDATA%\offline-office-tools\todos.json`(即 `C:\Users\<用户>\AppData\Roaming\offline-office-tools\todos.json`),关掉应用也不会丢;金额大写对第三位小数四舍五入,日期计算的工作日只算周一至周五(不含法定节假日)。

文本编码默认「自动识别」,按 BOM → 严格 UTF-8 → GB18030 的顺序判断;个别文件误判时手动选源编码,再点「重新读取」即可,不影响原文件。所有保存的输出都会在文件名上加操作后缀(如 `_左旋`、`_去重`、`_压缩`),避免与原文件混淆。

文本工具的去重/排序/去空行会保留源文件的换行风格(LF 保持 LF、CRLF 保持 CRLF)与末尾换行;超过 8 MB 的文件加载前会先确认。批量另存时逐个文件编码、立即写盘,不累积全部输出。

PDF 缩略图针对选中的第一个文件,单击选中/取消、Shift+单击连选,范围框与缩略图双向同步;不选页时「导出 PNG」与「提取文本」按全部页面处理。「重排页面」按点击顺序决定新页序,未点选的页保持原顺序排在末尾;导出 PNG/JPG 可设 DPI(72–600,默认 150 ≈ 2 倍),单页超过 3000 万像素(约 139MB RGBA)的页会跳过并在结束提示里报告,避免 32 位进程顶到内存上限,JPG 会自动铺白底,页面逐张写盘不占用内存。

PDF 压缩按「目标 DPI」对**内嵌位图**降采样并重编码 JPEG(默认 150 DPI,档位下拉提供普通 72 / 均衡 150 / 高质量 300,也可填自定义值),扫描件通常能降到原体积的 5%–30%;纯文字/矢量 PDF 几乎不会变小。非 DeviceRGB/DeviceGray 色彩空间、带 `Decode`/`DecodeParms`(predictor)/`Mask` 的图、CMYK/ICC 与真正带透明度的图都会自动跳过以保真,完成时会报告跳过张数。

所有操作都是「选文件 → 处理 → 另存」,原文件永不改动;同名输出自动加 `-1`、`-2` 后缀。图片工具在选中后只保留 240px 预览,处理时才由主进程读原图;超过 1200 万像素的图不做预览(只显示尺寸与大小),避免老 CPU 在选图阶段就整图解码。单张图片上限 4800 万像素(超限直接拒绝),单边 20000 像素,PDF 内嵌图上限 3600 万像素(更大会计入「跳过」),超限都是明确提示而不是崩溃。三个主要工具都提供「清空」按钮,可释放已选文件与缩略图/预览占用的内存。

图片工具的「合成 PDF」每张图一页:页面可选 A4(按图片方向自动横竖)/A4 竖向/Letter(自动横竖)/原图像素,留白 0–72pt,图片等比适应页内并居中,不裁切也不拉伸;A4/Letter 按「图片 DPI」(72–600,默认 150)把图片长边重采样到该尺寸对应的像素数,再受单页 3000 万像素预算收紧,大图不会被撑爆;JPEG 质量默认 85;勾选「按文件名排序」后按文件名(数字感知,如 `2` 排在 `10` 前)排序,默认保持列表顺序。「原图像素」模式直接把原图字节嵌进 PDF(不重编码),页面尺寸 = 图片像素 + 2×留白,DPI 输入自动禁用。

PDF 的页码范围支持 `1-3,5` 写法,中文逗号、`~`、`—`、全角数字都能识别;`3-1`、`0`、越界页码会被拒绝并提示。

## 开发与打包

```bash
npm install          # 首次安装(会下载 Electron 22.3.27)
npm run dev          # 构建并启动桌面应用
npm run build        # 只构建渲染层到 dist/renderer
npm test             # 纯逻辑单测 + PDF 整理产物回读(金额/日期/页码范围/换行/压缩白名单/路径/编码)
npm run dist         # 本地打包出 release/ 下的 ia32 zip(固定 --publish never)
```

`tests/pdfops.test.mjs` 用 Vite 的 SSR 加载器载入 `src/renderer/src/utils/pdfOps.js`,写出的 PDF 再用 pdf.js 回读校对(页码文本、中文子集字体、水印、CropBox、书签层级),不需要真机窗口。其中中文子集用例依赖系统 `simhei.ttf`,非中文 Windows(GitHub 的英文 runner 就没有)会自动 skip 并在日志里标 `SKIP`,这条以本机/中文 Windows 的结果为准。

打包无需 32 位宿主,x64 开发机直接交叉产出。若 Electron 二进制下载慢,可先设置镜像:

```bash
ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/ npm run dist
```

## 发布流程

正式包只由 GitHub Actions 产出,本地 `release/` 只是自测产物,不进仓库、不上传。

1. 改 `package.json` 的 `version`(如 `0.2.0`)并提交;
2. 打同名 tag 并推送:`git tag v0.2.0 && git push origin v0.2.0`;
3. `.github/workflows/release.yml` 在 windows-latest 上跑 `npm ci` → `npm test` → `npm run dist`,校验条目数/无原生二进制/`e_machine=0x014c`/`SHA-256`,再把 `离线办公工具-x.y.z-ia32-win.zip` 以 ASCII 名 `OfflineOfficeTools-x.y.z-ia32-win.zip` 挂到该 tag 的 GitHub Release(GitHub 资产名会剔除非 ASCII 字符,本地构建产物仍是中文名);
4. 手动触发(Actions → release → Run workflow)只跑构建并留 workflow artifact,不发 Release。

`npm run dist` 固定带 `--publish never`,本地不会误发;正式发布只走 tag 触发的 workflow,`npm ci` 前会先校验 tag 与 `package.json` 版本一致(不一致直接失败,避免 Release 里挂着旧版本号的文件名)。云端构建机的 rcedit 缓存是空的,workflow 会尽力下载一份写 exe 图标,失败则 exe 用 Electron 默认图标(窗口/任务栏图标不受影响);本机缓存里有 rcedit 时本地包图标正常。

## 发布前人工核对

原生「另存为/选目录」对话框无法自动化,以下步骤需人工在真实窗口点一遍(源码态 `npm run dev` 与解包后的 exe 各一次):

| 步骤 | 检查点 |
|---|---|
| PDF 整理 → 加页码(四种格式各一次) | 文件能正常打开,页码位置/颜色/起始号与设置一致 |
| PDF 整理 → 清除元数据 | 阅读器文档属性里标题/作者/主题为空 |
| PDF 整理 → 四周裁剪 | 页面四周按边距收进,内容未重排 |
| PDF 整理 → 自动生成书签 / 读取当前书签 / 按文本保存 | 书签层级与跳转页码正确 |
| PDF 整理 → 文字水印 | 平铺与居中都正确,角度、透明度、颜色与设置一致 |
| 图片工具 → 合成 PDF(3 张,分别试 A4 留白 24 DPI 150、勾选按文件名排序、原图像素) | 页数正确、顺序与列表一致(勾选后按文件名排);A4 页面横竖随图片方向,图片居中且在留白内;「原图像素」页面比原图各方向大 2×留白且 DPI 框禁用 |
| 小工具 → 待办 | 添加后关闭应用再打开,内容仍在 |
| 小工具 → 金额/日期 | 与预期大写、天数、工作日一致 |

## 版本约束

- `electron@22.3.27` 是最后一个支持 Win7/8/8.1 的版本(Chromium 108 / Node 16),**不要升级**。
- `pdfjs-dist@3.11.174`:4.x 要求更高版本浏览器特性,Chromium 108 上只能用 legacy 构建。
- `vite@4` + `build.target: 'chrome108'`:产物语法必须匹配 Win7 上的 Chromium 108。
- 依赖全部为纯 JS,无原生模块,`electron-builder.yml` 中已关闭 `npmRebuild`,并排除 pdfjs-dist 的可选原生依赖 `canvas`,包内不会混入任何原生二进制。

## 图标

`src/assets/icon.svg` 是源文件,`icon.ico`(16–256 多尺寸 BMP 条目,兼容 Windows 7)与 `icon.png` 由它生成;运行时窗口与任务栏图标来自 `icon.ico`。

打包时 `scripts/after-pack.cjs` 会尝试用 electron-builder 缓存里的 `rcedit` 把同一个图标写进 exe(Explorer 里的文件图标)。缓存里没有 rcedit 时该步骤自动跳过、构建照常成功,只是 exe 保留 Electron 默认文件图标。

不用 electron-builder 自带的 `win.icon` 流程:它在 Windows 上也会经 app-builder 下载 winCodeSign-2.6.0.7z(只是为了取出里面的 `rcedit-*.exe`),而该压缩包里的 macOS 符号链接在无特权机器上解压失败,会直接中断构建。

## 已知限制

- 打包不做代码签名(SmartScreen 可能提示未知发布者);exe 图标依赖打包机缓存中的 rcedit,缺失时仅文件图标退回默认。
- 「PDF 整理」的加页码与文字水印需要系统中文字体 `simhei.ttf`/`simkai.ttf`/`simfang.ttf`(中文版 Win7 自带黑体;只有英文系统的精简镜像可能没有),三个都找不到时这两个操作会明确报错,其他功能不受影响。
- 图片工具不支持输出 GIF(jimp 只读 GIF 首帧);PDF 加密文件无法处理,会提示"已加密或已损坏"。
- 合成 PDF 默认按 DPI 重采样;只有拿不到像素尺寸的图(预览失败:文件损坏,或 jpg/png 超过 4800 万像素)会跳过重采样、直接嵌入原图字节,PDF 会偏大;超过 4800 万像素的 bmp/gif 在固定页面下会处理失败并计入失败列表;「原图像素」模式对所有格式都是直接嵌原字节。
- 每次处理会整份读入内存,大文件(数百 MB PDF)可能占用较多内存。
